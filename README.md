# Система учёта заказов в небольшой пекарне

Учебный проект на C++17: товары разных типов рассчитывают цену по своим правилам, а корзина формирует чек с полиморфным выводом деталей. Валидация и исключения не позволяют создать некорректный товар или позицию заказа.

## Сборка и запуск

Из каталога `bakery-oop`:

```sh
cmake -S . -B build
cmake --build build
./build/bakery_demo
```

Проверки:

```sh
ctest --test-dir build --output-on-failure
```

## Пример вывода

```text
Корзина пуста.

Не удалось добавить товар: Вес хлеба должен быть конечным и больше нуля
Не удалось добавить товар: Количество товара должно быть больше нуля

Чек пекарни:
- Ржаной хлеб (тип теста: ржаное, вес: 750.00 г) x 2 = 360.00 руб.
- Слойка (начинка: вишня, вес: 150.00 г) x 3 = 450.00 руб.
- Праздничный торт (слоёв: 3, декор: ягоды) x 1 = 920.00 руб.
Итого: 1730.00 руб.
```

## Классы и правила расчёта

| Класс | Назначение |
| --- | --- |
| `Product` | Абстрактная основа: название, базовая цена, виртуальные методы цены и вывода деталей. |
| `Bread` | Хлеб с типом теста и весом; цена за 500 г × вес / 500. |
| `Pastry` | Выпечка с начинкой и весом; цена за 100 г × вес / 100 + доплата за начинку. |
| `Cake` | Торт со слоями и декором; базовая цена + цена дополнительных слоёв + доплата за декор. |
| `OrderItem` | Владеет одним товаром, хранит количество и пересчитывает стоимость строки при его изменении. |
| `Cart` | Хранит позиции заказа, добавляет и удаляет их, считает сумму и печатает чек. Индекс для `removeItem` начинается с нуля. |
| `BreadSpec`, `PastrySpec`, `CakeSpec` | Типизированные параметры создания товаров. |
| `ProductFactory` | Создаёт `std::unique_ptr<Product>` по строковому типу и соответствующей спецификации. |

Все поля классов закрыты. Сеттеры проверяют значения и выбрасывают `std::invalid_argument` при ошибке; фабрика также отклоняет неизвестные типы и несовпадение типа со спецификацией. В `main` ошибки при добавлении выводятся пользователю, после чего обработка заказа продолжается.
